# Preparing the Windows environment

**English** | [简体中文](prepare.zh-CN.md)

The preparation entry uses the committed tool and Python dependency identities. It checks the selected Visual Studio and SDK installation, acquires verified archives, prepares versioned tools, synchronizes the locked Python environment and records installed-file identities.

```powershell
pwsh -NoProfile -File scripts/dev.ps1 prepare -RequireWarp -WithEditor -EnableHooks
pwsh -NoProfile -File scripts/dev.ps1 doctor -RequireWarp
```

`-RequireWarp` includes the Warp dependency group. `-WithEditor` prepares the dedicated VS Code profile and project settings. `-EnableHooks` installs the pinned prek Git hook. The switches make these changes explicit in automation. Existing system compiler and SDK components are reused after their recorded identities match. Missing or differing system components produce diagnostics for review through the official installation workflow.

## Storage and repetition

| Location | Contents |
| --- | --- |
| `%LOCALAPPDATA%/HibikiPhysics/tools/<tool>/<version>` | Verified tool distributions |
| `%LOCALAPPDATA%/HibikiPhysics/cache/downloads/<sha256>` | Archive cache indexed by content hash |
| `%LOCALAPPDATA%/HibikiPhysics/cache/uv` | uv package cache |
| `%LOCALAPPDATA%/HibikiPhysics/vscode` | Dedicated editor data and extension directories |
| `.local/archives` | Checkout archive view, using hard links where supported |
| `.local/receipts` | Verified archive-to-installed-file inventories |
| `.local/environment.json` | Selected paths and preparation inputs |
| `.local/python-environment.json` | Lock identity, package versions and installed file hashes |
| `.venv` | Checkout Python environment |
| `.vscode` | Rendered local editor settings, tasks and launch configurations |
| `CMakeUserPresets.json` | Local preset aliases and archive paths |

Existing tools receive payload checks before reuse. Archive verification compares installed files with the selected archive contents. Python bytecode caches are treated as generated files; source files, interpreter binaries and libraries remain checked. VS Code adds installation metadata to extension manifests, so that metadata is separated from the original package manifest during archive comparison. Receipts retain the resulting installed-file hashes.

`uv.lock` is generated explicitly with the selected uv, reviewed and retained in the repository. Routine preparation uses `uv sync --locked`. Installed distributions are checked against the selected dependency graph and their RECORD hashes. The Python receipt binds those files to the lock digest. Optional generated bytecode stays outside the immutable-file inventory.

```powershell
pwsh -NoProfile -File scripts/dev.ps1 prepare -Offline -RequireWarp -WithEditor -EnableHooks
pwsh -NoProfile -File scripts/dev.ps1 prepare -ArchiveDirectory artifacts/env001/downloads -RequireWarp
```

`-Offline` requires cached archives and Python packages. `-ArchiveDirectory` imports already downloaded archives after hash validation. Incomplete downloads retain a `.part` file for a later range request. Hash failures preserve the evidence and stop preparation. Completed verified cache entries remain reusable.

## Editor and quality tools

The `HibikiPhysics` profile uses the selected VS Code distribution with dedicated user-data and extension directories. Its first initialization opens the project window. Templates live in `tools/vscode/`; the renderer writes machine-specific paths into `.vscode/`. The profile fixes extension versions and disables automatic editor/extension updates.

clangd uses the Windows Debug compilation database. The C/C++ extension supplies cppvsdbg, and project Python services use the selected environment through basedpyright and Ruff. The launch template provides a C++ probe configuration and a loopback Python debugpy attach configuration. Runtime LSP and debugger checks are part of the acceptance stage.

```powershell
pwsh -NoProfile -File scripts/dev.ps1 configure -Preset windows-debug
pwsh -NoProfile -File scripts/dev.ps1 build -Preset windows-debug
pwsh -NoProfile -File scripts/dev.ps1 test -Preset windows-debug
pwsh -NoProfile -File scripts/dev.ps1 check
pwsh -NoProfile -File scripts/dev.ps1 format
```

`check` validates formatting, Python types, project C++ diagnostics, file syntax, text conventions and bilingual links. `format` applies the selected formatters and safe Python lint fixes. C++ build preflight uses the C++ diagnostic scope, allowing its identity checks to run independently of Python package and editor integration.

The hook configuration uses pinned local tools and [prek built-in file checks](https://prek.j178.dev/reference/built-in-hooks/). Fast hooks operate on the staged file set. Isolated Git tests cover partial staging, retained unstaged changes, lint failure propagation and formatter-version rejection. Third-party license bytes are preserved outside project formatting.
