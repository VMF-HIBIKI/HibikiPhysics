# ADR-0010：插件化架构与生命周期

[English](0010-plugin-architecture-and-lifecycle.md) | **简体中文**

状态：Accepted（已接受）

日期：2026-11-01

更新：2026-11-21

相关工作：[ADR-0009：默认刚体研究配置](0009-incremental-potential-rigid-contact.zh-CN.md)。

## 背景

HibikiPhysics 支持围绕不同物理模型、状态表示、数值方法和执行后端开展研究。用户需要替换已有实现、扩展已有系统，并引入超出引擎初始能力分类的新功能。

DeepSeek Harness 为插件定义服务、依赖管理及可替换执行循环提供架构参考。HibikiPhysics 根据自身 C++ 运行时和物理计算需求应用这些原则。

## 候选方案

| 方案 | 取舍 |
| --- | --- |
| 固定引擎与预设算法插槽 | 预期内方案接入简单，扩展范围受内置插槽设计约束。 |
| 通用数学接口 | 提供共同装配语言，其假设限制新模型及数据需求。 |
| 开放插件协议与统一生命周期 | 选定方案，用户可以定义新能力，互操作规则由参与用户及组件定义。 |

## 决策

### 开放扩展

物理能力由插件提供。官方插件与用户插件使用相同的公开扩展机制。插件可以提供小型服务、包含自身状态的物理模型、完整子系统或其他插件的组合。

用户可以在独立开发的包中定义并注册新协议、配置类型、模型数据、运行状态、诊断及执行流程。注册机制支持新的能力身份，同时保持内核内置类型列表稳定。第三方插件可以定义协议，并通过共享协议包协作。

扩展契约覆盖三种用途：替换已有提供者、向已有子系统追加能力，以及提供拥有独立协议与执行流程的新子系统。

### 插件基本单元与能力

插件通过统一生命周期接入作用域，可以提供构建器、模型数据、数学接口、任务图或完整执行流程。提供服务的插件也可以定义供其他插件扩展该服务的方式。

例如，碰撞服务定义怎样为一对形状登记检测函数。场景编译时，选中的球–平面检测器将检测函数登记到负责处理仿真查询的同一个碰撞服务实例。推进时产生的接触数据归当前 World 所有。

### 能力声明与自动绑定

插件逐项声明提供的能力、实现的协议、适用的场景内容和所需服务。扩展入口的提供者定义匹配规则。对碰撞服务而言，文件中球和平面的先后顺序都对应同一项球–平面检测能力。一个插件可以为多种形状配对提供检测器。

引擎为支持的能力提供默认实现，加载场景时自动使用。扩展者可以注册新能力，也可以在实验配置中明确指定要替换的能力项。即使球–平面和球–球的默认检测器由同一个插件提供，替换球–平面检测也只改变这一项。使用该实验配置构建的场景都采用此替换，其他配置沿用各自的选择。

原生场景与资产层将文件内容转换为 [ADR-0013](0013-scenes-and-assets.zh-CN.md) 定义的中间场景描述。场景编译根据形状、碰撞过滤等事实确定所需能力，有明确实验替换的能力项采用替换实现，其余采用默认实现。选定的提供者就绪后，构建器将其实例绑定给消费插件，并通过带校验的生命周期入口挂载。编译后的场景记录各项能力的实际提供者及其来源，区分默认配置和实验替换。实际接触检测发生在仿真推进阶段。

缺少必需能力时，构建诊断指出需要该能力的场景内容。同一配置中的多个扩展替换同一能力项时，构建诊断指出该能力项及冲突插件。场景在这两类问题解决后方可运行。

### 插件作者的注册接口

每种扩展入口提供自己的类型化声明接口。球–平面检测器的作者通过碰撞服务的接口提交实现标识、形状配对和检测函数。形状配对只声明一次，用于匹配场景内容和检查函数签名。碰撞服务按协议将球和平面以约定顺序传给函数。

实验作者可以在加载场景前通过 `Add` 或 `Replace` 将声明注册到实验配置。

- `Add` 登记新的能力项。该项已有实现时，配置报告冲突，并提示有意替换时使用 `Replace`。
- `Replace` 接收新实现的声明，从中取得要替换的能力项。例如，球–平面检测器的声明已经标识目标配对，实验作者只需传入该声明一次。

配置中的声明可供多个场景复用。每次构建时，构建器负责挂载选中的实现。碰撞扩展入口提供的适配器统一声明对碰撞服务的依赖，向该场景的碰撞服务实例登记检测函数，并将注销凭据交给此次挂载的作用域。

安装包的 C++ 接口通过 `CapabilitySlot<T>` 将能力名、协议类型及只读限定关联起来。描述符的 `Factory` 和 `Borrow` 声明将目标入口与实现名传给 `Add` 或 `Replace`。复制配置得到独立的选择记录。首次替换要求引用类型与注册项一致，再次替换同一入口会报告冲突。应用可以通过显式组合函数提供默认配置。

`Build` 和 `Mount` 先校验请求的入口类型，再运行工厂。每个作用域对每个所需的工厂入口只构造一次，并持有返回对象。借用的提供者由调用者持有。作用域按取得资源的逆序清理，先撤销挂载登记，再释放工厂创建的提供者。构造或挂载失败时沿用同一顺序。`MakePlugin` 根据同一组类型化入口生成需求声明和回调参数顺序。需要保存登记凭据的回调还可以接收挂载上下文。

### 依赖声明与绑定

插件声明自己需要的能力。构建器根据默认配置和显式实验替换确定提供者，并执行组件需要的检查。依赖绑定与运行组合在运行期间保持固定，修改遵循 ADR-0019 的重新配置与编译构建流程。插件版本、依赖获取和分发继续由用户管理。

例如，摩擦插件声明需要线性求解能力，用户可以为不同实验分别绑定不同求解器提供者。能力协议定义双方的调用约定，C++ 接口通过名称标识入口。`Require<T>` 记录 `std::reference_wrapper<T>` 的类型，保留 `T` 的只读限定。调用者通过 `std::ref` 或 `std::cref` 绑定对象。`Plugin::Mount` 收集声明，调用 `PluginContext::Validate` 校验绑定，再调用受保护的 `OnMount` 回调。遇到首项缺失或类型不匹配的绑定时，校验抛出 `std::invalid_argument`，消息包含入口名和原因。调用者决定如何处理失败。

### 依赖与执行顺序

构建依赖说明插件准备和绑定时需要哪些能力或数据；每步执行顺序说明计算何时发生。所选执行流程安排顺序、循环及重复调用。例如，接触数据访问入口在构建时绑定，接触更新和摩擦求解在每步按流程执行，迭代也可以多次请求接触更新。

执行流程自身可以由插件提供。依赖连接和计算先后关系分别表达，具体任务图及调度协议由相应插件定义。

### 插件对象与 World 数据

算法实现及只读配置在满足共享条件时可以供多个 World 使用。接触历史、摩擦状态及求解工作区等可变运行数据按 World 隔离。插件定义数据创建、分配和释放方式，并接入统一生命周期。

逐 World 对象与批量数组均为可选存储方式。隔离要求针对逻辑状态，具体内存布局及插件对象数量由实现确定。跨插件持有的能力引用遵循提供者的生命周期和并发访问约定，批量并行遵循 ADR-0011。

### 协议归属与组合

协议属于使用它的插件体系。插件身份、版本、依赖、提供者选择、组合及升级由用户管理。参与者定义自身的互操作、数据所有权及执行规则。场景编译构建执行所选组件需要的检查，并报告结果。具体协议及检查机制保持开放。

势能、残差、约束、投影和矩阵自由算子接口保留为具体算法体系的候选。具体数学接口、强制能力分类及通用的模型／离散／求解分层保持待定。这些概念可以用于组织默认实现，其接口通过真实扩展案例逐步形成。

模拟编排本身可以替换。默认的预测、接触、求解、提交顺序属于默认时间推进实现。插件可以公开内部扩展入口，也可以提供完整的替代流程。数据访问、同步、执行顺序与状态修改边界属于各流程的显式契约。

### 统一生命周期

运行时提供统一的注册、初始化和清理机制。用户或所选编排组件安排依赖及初始化顺序。插件登记函数或订阅事件时，该注册项归执行登记的插件作用域所有。销毁时，待进行中的调用结束，作用域在相应服务仍然可用时撤销自己的注册项。挂载中途失败时，已经完成的注册沿用这套清理规则。

插件声明实例作用域，区分不可变模型数据、持久模拟状态及可重建缓存。不同场景可以选择不同实现，并拥有独立的可变状态。跨插件访问遵循明确的所有权与生命周期契约。

所选执行流程定义检查点、回滚、提交及恢复的参与方式。支持重启的组件定义自身状态检查及重建规则。失败传播和恢复由用户设计，生命周期清理遵循资源所有权。

统一生命周期表示共同的管理规则。状态存储机制、并发原语和二进制加载行为属于后续设计。

### 错误处理扩展

错误处理通过插件扩展。项目将提供官方示范插件与应用，展示诊断收集、结果汇总及调用者自行选择处理动作。错误分类、信息格式、处理协议、状态有效性规则和恢复策略由用户定义，具体接口保持待定。示例记录失败 World 及其时间／求解上下文，由应用选择后续动作。

### 默认研究配置

[ADR-0009](0009-incremental-potential-rigid-contact.zh-CN.md) 定义官方默认刚体研究配置，包括混合多体坐标、增量势能惯性、柔顺法向接触、理想硬闭环，以及采用半光滑 Newton 的非光滑静摩擦。

其中的物理与数值要求适用于该配置。其他插件组合可以选择不同模型和求解器，并声明各自的行为与验证要求。默认组合通过公开扩展机制组装，作为可复现的参考配置。

运行记录标识实际插件组合、实现版本、参数及执行策略。摩擦与阻尼属于可扩展能力；默认关节摩擦方向为保持零速承载的非光滑干摩擦，并可单独叠加黏性阻尼。具体关节摩擦协议与离散方式通过后续规格确定。

## 影响

扩展自由度包含协议、数据和流程定义。共享协议支持兼容体系内的复用与替换。用户选择适合自身组合的依赖管理、适配及验证方式，官方示例记录实际组合以支持复现。

[ADR-0011](0011-multi-world-batch-simulation.zh-CN.md) 将多 World 批量仿真及插件并行隔离确定为核心要求。专用数据布局保留为可选设计，依赖绑定在场景编译构建时完成。后续 C++ 接口、注册标识、静态／动态加载、二进制 ABI 及加载机制属于后续设计。运行组合按 [ADR-0019](0019-world-configuration-and-runtime-inputs.zh-CN.md) 保持固定。安装包已实现插件基类和绑定校验。

## 验证

验证状态：安装包测试覆盖默认注册、实验替换、绑定校验与挂载作用域清理。根据桥接后的场景生成需求、碰撞适配器、多 World 行为和调度等待实现。

- 完全通过公开扩展机制构建官方默认组合。
- 从独立项目接入具有自定义历史状态的摩擦插件，验证生命周期与回滚行为。
- 接入自定义多体表示和求解器，复用几何服务并拥有自身状态与数学模型。
- 在用户包中定义服务协议，使两个用户插件通过该协议协作。释放一个作用域后，检查其注册项已撤销，其他作用域登记的条目仍然可用。
- 通过插件组合替换完整时间推进流程。
- 为同一消费插件分别绑定不同能力提供者，验证用户选择与实际连接一致。
- 在示例流程中分别验证构建依赖及每步顺序，并覆盖同一步内重复调用。
- 使用共享只读内容及独立 World 状态运行多个实例，检查重置与释放的隔离行为。
- 在同一进程中运行采用不同实现及独立状态的两个场景。
- 验证组件自定义检查、初始化清理、销毁及官方错误处理示例，记录实际组合以支持复现。
