# ADR-0011：多 World 批量仿真

[English](0011-multi-world-batch-simulation.md) | **简体中文**

状态：Accepted（已接受）

日期：2026-11-01

相关工作：[默认刚体研究配置](0009-incremental-potential-rigid-contact.zh-CN.md)、[插件化架构与生命周期](0010-plugin-architecture-and-lifecycle.zh-CN.md)。

## 背景

具身智能应用需要大量独立仿真实例，用于训练、评估、系统辨识和参数研究。多 World 批量仿真属于核心架构与交付要求。MotrixSim 将共享模型数据与独立模拟数据分离的组织方式提供参考。

World 表示逻辑隔离的仿真实例。同一 World 内相互作用的机器人和其他物体组成一个物理场景。跨 World 批量执行组织多个独立实例。

## 候选方案

| 方案 | 取舍 |
| --- | --- |
| 每个实例复制完整模型 | 所有权直观，重复拓扑与资产增加内存和初始化成本。 |
| 共享模型并维护独立实例状态 | 选定的默认批量组织，通过明确的隔离与参数覆盖复用模型。 |
| 批量运行异构模型和配置 | 架构支持方向，兼容分组共享执行策略，性能分别评估。 |

## 决策

### 共享模型与独立状态

兼容 World 共享只读几何资产、机构拓扑和默认参数。每个 World 独立拥有可变运动状态、控制输入、传感器状态、接触与摩擦历史、积分历史、求解状态、随机状态、模拟时间及诊断。逐 World 模型参数按 [ADR-0019](0019-world-configuration-and-runtime-inputs.zh-CN.md) 在场景编译构建时固定。可变临时存储遵循明确的所有权或同步规则。

物理交互限定在单个 World 内。渲染偏移仅影响展示。共享服务和缓存声明并发与生命周期契约。模型与状态的逻辑划分允许 ADR-0010 所规定的插件自定义存储。

### 批量范围与应用边界

相同拓扑、独立状态作为主要性能路径，编译构建前采样的逐 World 参数支持该路径上的域随机化。不同模型或插件组合可以在同一进程中共存，并按兼容组执行调度。

核心工作流支持批量控制输入、仿真推进、状态／观测读取，以及按身份、索引或掩码选择 World。任务、奖励、回合终止和课程学习属于上层应用，未来可以由独立 Lab 项目提供，其与推进和重置之间具有明确的执行顺序语义。[ADR-0012](0012-usage-and-runtime-modes.zh-CN.md) 确定短期 Python 支持本地场景搭建、仿真和查看，同时保留无窗口批量引擎能力。

CPU 多 World 并行执行属于必达交付能力。Warp 保持为可扩展执行后端及加速研究方向。插件与批量契约考虑后端需求，具体组合声明实际后端覆盖。

### 部分重置与恢复

选定 World 可以独立重置，其他 World 的状态保持原样。重置按声明的策略覆盖全部参与插件状态，包括接触历史、摩擦变量、积分历史、控制、传感器、时钟、求解缓存及随机化状态。重置沿用已编译模型参数并恢复配置的初始状态，随机流恢复遵循声明的重置策略。

重置及明确支持的运行输入在确定的安全执行边界生效。完成或终止步骤的观测与重置后的观测能够明确区分。自动重置行为由应用组合声明。

官方示例流程按 World 报告可隔离的数值失败，并示范按自身回滚策略保留上一次接受状态，由调用者选择后续动作。用户按 [ADR-0010](0010-plugin-architecture-and-lifecycle.zh-CN.md) 自行定义执行流程的失败传播、状态有效性与恢复方式。进程／设备故障的影响范围由所选后端及流程说明。

### 域随机化

受支持的参数在场景编译构建前逐 World 配置，共享模型默认值保持只读。初始状态配置、质量、惯性、摩擦和驱动参数作为目标类别，实际支持范围及合法取值由对应插件声明。场景编译构建固定这些取值，并生成相应派生数据。

模型参数重新采样及结构变化进入新一轮配置与场景编译构建流程。随机化分布与采样策略允许扩展，逐 World 采样来源及种子支持独立于工作线程分配的复现。运行交互通过已编译配置明确开放的输入进行。

### 插件并行隔离

插件声明实例作用域、共享资源、并发访问规则及支持的执行模式。有状态模拟数据归属于对应 World。跨 World 共享采用明确的不可变或同步资源。

官方默认组合必须通过多 World 隔离、部分重置和并行执行验证。用户插件可以提供兼容调度下的单实例执行，也可以提供专用批量执行。用户管理组合与调度，所选组件定义自身支持的并发使用检查。

插件生命周期、重置、回滚和销毁在修改或释放状态之前协调进行中的工作。调度与存储选择保持 ADR-0010 的开放协议、数据和流程扩展原则。

### 复现与性能

运行记录标识模型与资产版本、插件组合、已编译逐 World 参数、逐 World 随机状态来源、推进／重置序列及执行策略。官方实验针对自身配置与后端说明复现主张，并以各自标准评价跨平台／后端对照。用户按 ADR-0015 自行定义应用验收。

性能评估包含批量吞吐、多核扩展、每 World 内存、初始化／重置成本、接触与求解负载不均衡，以及向训练应用传输数据的成本。World 数量与吞吐目标结合代表机器人及实测硬件确定。

## 影响

隔离、部分重置和参数变化从架构起点进入设计。共享不可变模型减少重复数据，独立历史与已编译逐 World 参数需要明确所有权。不同 World 的求解工作量差异需要在后续调度策略中进行性能评估。

具体 C++／Python 接口、批量内存布局、线程池、调度算法、同步机制及设备传输实现保持待定。[ADR-0016](0016-time-advancement.zh-CN.md) 已确定默认同步批量交互，并支持可扩展的异步推进方向。本记录确定能力与行为要求，实现待完成。

## 验证

验证状态：待实现与批量实验。

- 在相同模型、输入和随机状态下，按声明的数值复现标准比较单独运行与批量运行的 World。
- 重置选定子集，验证相关插件状态及其他 World 状态的保持。
- 以不同逐 World 参数编译构建共享模型实例，检查派生数据、模型只读性和行为隔离。
- 在不同工作线程分配下重复编译前采样，并验证部分重置保持已编译参数。
- 验证逐 World 可恢复求解失败、回滚及后续重置或重试。
- 并发运行不同模型与插件组合，检查资源生命周期及并行访问声明。
- 测量吞吐、内存、重置开销、负载不均衡及训练侧数据传输。相关用例采用参数化测试集中组织，控制测试文件数量。
