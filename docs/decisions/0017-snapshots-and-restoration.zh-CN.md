# ADR-0017：状态快照与恢复

[English](0017-snapshots-and-restoration.md) | **简体中文**

状态：Accepted（已接受）

日期：2026-11-01

相关工作：[插件生命周期](0010-plugin-architecture-and-lifecycle.zh-CN.md)、[多 World 仿真](0011-multi-world-batch-simulation.zh-CN.md)、[场景产物](0013-scenes-and-assets.zh-CN.md)、[时间推进](0016-time-advancement.zh-CN.md)。

## 背景

模拟快照支持失败排查、恢复续跑和分支实验。快照描述一致的已接受状态，以及解释和继续运行该状态所需的依赖。

## 候选方案

| 方案 | 取舍 |
| --- | --- |
| 保存可见运动数据 | 适合轨迹播放，续跑依赖额外的求解器与插件状态。 |
| 保存续跑状态及模型／插件身份 | 选定方案，保存必要物理、时间与插件历史，并明确兼容性。 |

## 决策

### 保存状态

快照标识场景／模型、资产、物理参数、插件实现／版本和执行配置，保存位置、朝向、速度、关节状态、已编译逐 World 参数的身份及取值，以及影响续跑的接触、摩擦、积分和求解历史。

时间、控制输入、随机状态及已接纳命令的执行位置在影响续跑时纳入保存。各插件声明必需持久状态、可重建数据及临时工作区。分类依据其对后续行为的影响确定；热启动数据可能影响有限迭代结果，需要明确处理。

模型与资产可以通过稳定身份引用。自包含打包、存储格式、压缩及增量保存属于后续选择。

### 恢复范围

支持失败回滚、保存后续跑、从同一快照创建独立分支，以及恢复选定 World。其他 World 保持当前状态。分支记录来源快照和新运行身份，恢复使用兼容的已编译配置。参数变化按 [ADR-0019](0019-world-configuration-and-runtime-inputs.zh-CN.md) 进入新一轮配置与场景编译构建流程，并明确状态迁移及历史处理策略。

独立 World 快照记录各实例自己的模拟时刻，协调批量保存遵循声明的共同边界。涉及共享应用状态时，应用提供对应一致性契约。仅查看加载明确说明可读取内容及可用续跑能力。

### 一致保存与异步执行

保存采用已接受状态边界。进行中的试探和设备工作按照执行策略完成、撤销或隔离，随后形成稳定快照。具体等待与复制机制保持待定。

恢复协调状态写入权与进行中的任务。恢复后的运行身份用于区分旧异步结果。输入历史标识已应用及已接纳待执行命令，使重放具有明确执行位置。线程、设备指针和任务句柄作为运行资源重建；命令语义的可序列化和外部资源恢复由插件声明能力。

### 插件兼容性

下述兼容及失败行为描述官方恢复流程。用户管理插件版本与依赖，所选恢复组件按 [ADR-0010](0010-plugin-architecture-and-lifecycle.zh-CN.md) 定义检查、迁移及错误处理方式。

各有状态插件声明快照边界、保存数据版本、加载／校验、重建及受支持的迁移行为。保存先检查参与能力，再生成完整快照。恢复依次校验依赖与数据、构建并检查恢复状态，最后发布可运行 World。

| 情况 | 行为 |
| --- | --- |
| 模型及插件配置匹配 | 按声明的续跑保证恢复。 |
| 插件版本明确兼容 | 加载、校验并记录实际实现身份。 |
| 提供迁移能力 | 显式转换，记录源／目标版本及新的保证范围。 |
| 必需插件缺失或状态无法解释 | 报告续跑恢复受阻原因，保留快照。 |
| 展示能力缺失 | 按能力允许查看或物理续跑，明确报告可用范围。 |

模型／拓扑变化进入新一轮配置与场景编译构建流程，并采用显式迁移或分支策略。使用默认值初始化必需历史属于明确的重新初始化操作。版本身份、兼容性和成功数值复现分别验证。

## 影响

该方案通过完整插件参与支持单个及选定批量恢复。状态恢复、数值续跑复现及迁移后续跑具有独立的保证范围。具体接口、文件格式、迁移接口、异步保存、同步及性能策略保持待定。实现待完成。

## 验证

验证状态：待实现。

- 按声明的复现标准比较连续运行与保存／恢复后的续跑。
- 恢复或分支选定 World，检查其他实例保持原样。
- 验证插件历史、随机状态、时间及输入执行位置。
- 验证存在进行中任务时的保存／恢复，并通过运行身份识别旧结果。
- 检查插件缺失、兼容升级、显式迁移及恢复失败时原有效状态的保留。
