# ADR-0003：提交钩子与验证流程

[English](0003-commit-hooks-and-validation.md) | **简体中文**

状态：Accepted（已接受）。

日期：2026-10-31。

验证状态：本地钩子与检查通过，远程 PR CI 属于后续工作。
当前 Windows 证据见[验收记录](../environment/acceptance.zh-CN.md)。

## 背景

项目需要提交前的快速反馈，以及 CI 中可复现的验证。[ADR-0002](0002-editor-debugging-and-code-quality.zh-CN.md)定义格式化与分析规则。钩子使用与编辑器、命令行相同的版本化工具。

## 决策

提交钩子执行工具选定为 prek 0.5.9，由 uv 在项目开发依赖和 uv.lock 中固定精确版本。配置使用 .pre-commit-config.yaml。钩子启用安排在后续环境初始化阶段。

本地工具钩子使用 repo: local 和 language: system。Ruff 命令通过 uv 锁定模式解析到 Ruff 0.17.3。项目包装脚本通过工具链基线解析 clang-format 22.1.6。环境准备提供所需工具，钩子启动时检查可用性和版本，对偏差报告准备步骤。

适用的文件检查使用固定版本 prek 的内置实现。后续引入的外部钩子仓库记录明确的修订版本与来源。

## 验证分层

| 层次 | 时机 | 范围 |
| --- | --- | --- |
| 快速检查 | 每次提交前 | 暂存文件格式化、Python lint、文件有效性和冲突检查 |
| 完整检查 | 本地主动执行及 PR CI | 格式验证、basedpyright、clang-tidy、构建与测试 |
| 专项检查 | 相关变更及里程碑验收 | Sanitizer、物理回归和性能基准 |

快速检查目标耗时为数秒到十几秒。依赖构建的分析归入完整检查。共享配置变化在完整验证中触发对应的扩大范围检查。

## 快速检查与本地修复

- Python lint 使用 ruff check --fix，采用安全修复策略。
- Python 格式化使用 ruff format。
- C++ 格式化使用固定版本 clang-format。
- 文件检查覆盖 JSON、YAML、TOML 语法，合并冲突标记及大小写冲突文件名。
- 文本规范覆盖文件末尾换行和行尾空白，保留 Markdown 有意设置的硬换行及既定换行策略。
- 文档检查验证双语配对和语言链接，审查负责语义对应。

本地检查接收暂存文件集合。自动修复生成可审查的工作区修改，开发者检查并暂存后再次提交。钩子验证覆盖部分暂存场景，并保留其他工作区变更。生成文件、第三方源码、虚拟环境和构建产物沿用 ADR-0002 的排除规则。

## 本地与 CI 执行

本地修复与 CI 验证共享规则文件，通过钩子入口或包装脚本模式区分写入和检查：

| 本地修复 | CI 验证 |
| --- | --- |
| ruff check --fix | ruff check |
| ruff format | ruff format --check |
| clang-format 写回模式 | clang-format 检查模式 |

CI 执行只检查操作并记录诊断。完整验证同时运行 basedpyright、clang-tidy、构建和测试。后续包装脚本向本地提供相同的只检查入口。需要完整项目上下文的检查始终读取相应上下文，变更文件集合用于决定触发条件。

PR CI 验证 type: 具体内容 的标题格式、一个实现 Issue 的关联关系，以及 Issue 与 PR 标题完全一致。提交钩子检查本地文件，PR CI 读取远程元数据。标题检查在相关 PR 元数据变化及代码验证时执行。远程工作流配置属于后续实施工作。

## 影响与验证

项目维护钩子包装脚本和文件选择规则。统一工具来源保证编辑器、CLI 与钩子版本一致。快速反馈与完整验证采用各自的执行成本和时机。

- [x] 钩子配置通过 prek 0.5.9 校验。

- [x] 暂存文件检查、本地修复和部分暂存行为符合约定。
- [ ] CI 只检查执行保持检出内容并报告失败。
