# ADR-0013：场景与资产

[English](0013-scenes-and-assets.md) | **简体中文**

状态：Accepted（已接受）

日期：2026-11-01

相关工作：[插件化架构与生命周期](0010-plugin-architecture-and-lifecycle.zh-CN.md)、[多 World 批量仿真](0011-multi-world-batch-simulation.zh-CN.md)、[使用方式与运行模式](0012-usage-and-runtime-modes.zh-CN.md)。

## 背景

HibikiPhysics 需要程序化场景构建、可复用原生场景描述及机器人／几何资产导入。不同源格式具有不同的结构与物理语义。统一中间层为这些输入提供通往模型和插件组合的公共路径，同时保留用户自定义扩展能力。

## 候选方案

| 方案 | 取舍 |
| --- | --- |
| 各导入器直接构建运行时内部结构 | 格式集成直观，校验和运行时假设分散在各导入器中。 |
| 采用某个外部格式定义引擎场景模型 | 复用已有描述，扩展范围受该格式约定影响。 |
| 原生可扩展中间层与格式插件 | 选定方案，通过公共校验和构建支持多种格式及自定义模型语义。 |

## 决策

### 场景来源与原生中间解析层

引擎原生提供中间解析与场景描述层。C++／Python 程序化构建、原生场景加载和外部格式适配器进入共同的场景语义及校验／模型构建路径。

概念流程为：

```text
源格式 -> 格式适配器插件 -> 可扩展中间场景描述
程序化构建／原生场景加载 -> 中间场景描述
中间场景描述 -> 校验与模型构建 -> 模型及插件组合
模型 -> 独立 World 实例
```

中间层表达刚体／连杆、关节与连接、几何、质量属性、材料、驱动、初始条件和资产引用，承载场景与物理模型语义。选定的下游插件决定求解坐标、运行时布局及装配方式。

### 格式适配器

官方 URDF 与 MJCF 适配器作为主要机器人导入目标，按照记录的功能覆盖逐步验收。USD 保留为后续场景交换方向。网格资产具有独立导入路径，具体文件格式覆盖随后确定。

官方与用户适配器使用相同的公开注册及转换机制。用户可以在独立包中增加格式，复用后续校验、模型构建和多 World 能力。导入报告提供适配器身份、版本、选项和源资产追溯信息。

各适配器定义单位、坐标约定、引用、拓扑及物理属性的映射，分别报告解析覆盖与端到端物理支持。尚未支持或语义存在差异的特性产生诊断，采用明确的错误、警告或用户选择的替代策略。报告保留源位置／名称及实际采用的转换或替代方式。

### 用户自定义扩展

插件可以定义新的场景元素、属性、模型数据和资源种类，并提供相应校验与构建处理。扩展身份及依赖信息用于解析对应处理器，同时保持内核内置类型列表稳定。

原生场景持久化通过声明的保存／加载能力支持插件自有配置与模型内容。处理器缺失或版本不兼容时产生明确诊断。未知扩展数据的原样保留与可执行仿真支持分别声明语义。具体扩展 schema 与注册接口保持待定。

### 场景、快照与实验记录

| 产物 | 职责 |
| --- | --- |
| 场景／模型描述 | 结构、资产引用、物理参数、初始条件及选定的插件配置。 |
| 状态快照 | 一个 World 的当前权威状态及受支持续跑所需的插件历史，并引用兼容模型与配置。 |
| 实验记录 | 实际模型／插件身份、输入、参数、随机化、执行策略、结果及诊断。 |

多个 World 可以共享同一个模型及其不可变资产，各自维护独立状态及场景编译构建时固定的逐 World 参数。资产身份与插件版本追溯信息关联这些产物。播放与可继续模拟的恢复沿用 ADR-0012 中分别定义的保证。

### 资产预处理

网格处理、质量属性计算、凸分解和 SDF 生成属于可扩展预处理能力。生成产物记录源资产身份、预处理实现／版本及参数，用于识别和复现缓存结果。

原始几何保留用于表面采样、可视化、验证和重新生成等用途。碰撞表示与质量属性来源明确选择。具体 SDF 存储、构建、插值和导数路线保持待定，后续专项调研。

## 影响

统一中间层将源格式处理与运行时组织分离，并支持共同校验路径。格式适配器及用户扩展需要清晰的转换语义、追溯信息和处理器兼容性。源资产的实际仿真支持由选定插件及验收用例确定。

具体数据结构、原生文件语法、schema／版本机制、解析库、资源解析规则、预处理算法及 C++／Python 接口保持待定。本记录确定已接受的架构与职责，实现待完成。

## 验证

验证状态：待实现与导入／扩展验收。

- 通过程序化构建、原生及外部输入创建等价受支持场景，比较模型语义与代表性仿真行为。
- 从独立项目通过公开扩展机制增加格式适配器。
- 增加用户定义场景元素及其校验、构建、持久化处理器，检查兼容组合下的保存与加载。
- 检查尚未支持的属性、单位／坐标映射、资产或处理器缺失、版本不匹配时的源关联诊断。
- 验证受支持机器人层级、连接及质量属性在转换与模型构建中得到保留。
- 从同一个构建模型创建多个独立 World，检查共享资产身份和状态隔离。
- 检查预处理缓存追溯，以及场景加载、快照恢复和实验回放的语义区分。相关用例集中组织，控制测试文件数量。
