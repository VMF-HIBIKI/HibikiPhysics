# ADR-0016：时间推进

[English](0016-time-advancement.md) | **简体中文**

状态：Accepted（已接受）

日期：2026-11-01

相关工作：[插件化架构](0010-plugin-architecture-and-lifecycle.zh-CN.md)、[多 World 仿真](0011-multi-world-batch-simulation.zh-CN.md)、[运行模式](0012-usage-and-runtime-modes.zh-CN.md)。

## 背景

本地交互与批量仿真需要明确的模拟时间和状态提交语义。模拟时间、推进策略与执行调度分别承担职责。

## 候选方案

| 方案 | 取舍 |
| --- | --- |
| 固定全局循环与时钟 | 协调简单，不同 World 与算法绑定到同一推进策略。 |
| 插件化推进、逐 World 时间及明确执行语义 | 选定方案，支持默认批量操作及可扩展的异步或独立推进。 |

## 决策

下述状态／时间及失败报告行为描述官方参考流程。用户可以按 [ADR-0010](0010-plugin-architecture-and-lifecycle.zh-CN.md) 定义自身推进、状态有效性、失败传播和恢复协议。多 World 隔离与已编译配置固定保持为所选运行实例的边界。

时间推进通过插件替换。时间推进实现组合逐 World 模拟时钟、步长／子步与目标时刻策略、求解／重试／提交行为，以及暂停和单步控制。执行服务可以提供任务提交、并行调度及完成通知，插件也可以提供完整组合流程。

默认提供同步批量交互语义，内部支持多 World 并行执行。架构保留异步提交与独立 World 推进能力。批量策略明确声明选定 World 是到达共同目标时刻，还是分别报告独立推进时刻。

模拟时间随已接受状态推进。试探求解和重试保持明确的提交边界。每个 World 拥有独立时间与推进状态。控制输入声明生效时间，结果标识所属 World、模拟时刻和推进请求。

重置、回滚与恢复协调进行中的工作，将时间与物理状态、插件历史共同恢复。失败推进按所选策略报告已接受进度和停止原因。待执行工作及外部交互遵循所属流程的契约。

实际时间节奏属于运行策略：无窗口实验可以按资源能力尽快推进，交互应用可以请求播放节奏。两类策略都具有明确的模拟时间语义。

具体时间表示、接口、默认步长／子步选择、重试算法、任务调度、同步及时间状态序列化保持待定。用户按照 ADR-0010 扩展或替换协议与流程。

## 影响

同步与异步入口可以共享物理推进规则。独立时钟、输入时序及结果身份需要明确协调，尤其涉及部分重置与恢复时。本次接受范围为行为及扩展原则，实现待完成。

## 验证

验证状态：待实现。

- 检查成功推进及重试中的已提交时间与物理／插件状态一致性。
- 验证所选批量策略下的暂停、单步、重置与回滚。
- 按记录的复现条件比较等价的同步与异步运行。
- 验证目标时刻报告、控制应用顺序及完成时间不同的 World 隔离。
- 验证重置／恢复期间的进行中任务、结果身份和状态所有权。
