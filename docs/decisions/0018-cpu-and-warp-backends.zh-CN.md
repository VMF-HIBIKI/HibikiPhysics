# ADR-0018：CPU 与 Warp 后端职责

[English](0018-cpu-and-warp-backends.md) | **简体中文**

状态：Accepted（已接受）

日期：2026-11-01

相关工作：[默认研究配置](0009-incremental-potential-rigid-contact.zh-CN.md)、[插件化](0010-plugin-architecture-and-lifecycle.zh-CN.md)、[多 World 仿真](0011-multi-world-batch-simulation.zh-CN.md)、[官方实验](0015-experiments-and-acceptance.zh-CN.md)。

## 背景

首期研究路径优先完成 CPU 仿真、算法开发与调试。Warp 提供可选的并行计算路径。插件扩展需要明确后端能力及组合兼容性。

## 候选方案

| 方案 | 取舍 |
| --- | --- |
| 各后端同步交付相同算法和功能 | 各后端的开发进度与实现选择相互耦合。 |
| 优先完成 CPU 研究路径，通过插件扩展后端覆盖 | 选定方案，支持渐进实现及明确的能力覆盖。 |

## 决策

### 职责与覆盖范围

CPU 承担首期完整的仿真、调试与正确性实验研究路径，并作为持续维护的后端。Warp 作为可选计算后端，接入顺序依据实验价值及批量并行适用性确定。

后端决定计算在哪里执行，求解器决定采用什么算法。求解器插件可以支持一个或多个后端。默认研究配置优先在 CPU 实现。其他组合可以提供不同算法与功能覆盖。

各后端共用物体、关节及材料等场景与模型语义，分别构建适合自身执行需要的运行数据。能力声明说明支持的语义与配置。

### 插件组合与多 World 执行

用户管理后端与插件组合。所选组件定义支持的执行条件，在场景编译构建时执行自身必要检查，并通过自行选择的诊断机制报告能力缺口。[ADR-0010](0010-plugin-architecture-and-lifecycle.zh-CN.md) 确定这一责任边界。

批量运行依据模型、插件组合及后端能力对 World 分组，保持各 World 状态独立。初期在创建运行实例时选择后端，运行中的迁移属于后续扩展能力。

跨 CPU 与 GPU 的组合明确表达数据交换及同步要求，性能统计覆盖相应成本。具体组合及调度机制保持待定。

### 诊断与评价自主权

项目提供诊断数据及扩展机制。用户自行决定应用验收指标、阈值、参考结果和评价流程。兼容性检查与求解器结果报告保留各自的运行职责。

对于相同模型与算法，官方实验在记录精度及运行条件的基础上比较状态、残差、守恒量及数值误差。对于不同算法，实验选择适用的物理行为、求解质量、稳定性和成本指标。逐位复现主张说明适用配置。性能报告附带求解质量证据。这些约定适用于 ADR-0015 中的官方实验。

### 待定事项

设备接口、数据布局、传输、调度、迁移机制及 Warp 具体实现里程碑保持待定。

## 影响

CPU 研究路径可以独立推进，Warp 及用户自定义后端逐步扩展可用配置。明确的能力声明呈现组合边界，各后端承担自身运行表示及实现成本。

## 验证

验证状态：待实现与后端实验。

项目开发检查将覆盖能力诊断、兼容组合及 World 隔离。官方后端实验记录各自的评价条件与证据。
