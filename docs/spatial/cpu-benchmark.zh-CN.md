## 实测结果

在 AMD Ryzen 7 9700X、Windows 11 x64 和 clang-cl 22.1.6 Release 上，Morton 树在四个静态场景中构建耗时最少。无栈树在这四个场景上执行整批 128 次盒查询和生成全部自相交对的耗时均最少。各耗时取五个独立进程的中位数，内存取五次进程峰值中的最大值。

**静态几何。** 每个耗时单元格依次给出构建、整批盒查询和生成全部自相交对的毫秒数。前两列数字为返回的 ID 总数和无序对数。

| 场景 | 盒查询 ID | 候选对 | 中位数树 | Morton | BVH4 | SAP | 无栈 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 稀疏 | 173 | 348 | 0.279 / 0.035 / 0.072 | 0.140 / 0.033 / 0.066 | 0.186 / 0.039 / 0.084 | 0.164 / 0.085 / 0.178 | 0.144 / 0.032 / 0.058 |
| 密集 | 42,127 | 211,532 | 0.271 / 1.489 / 13.580 | 0.129 / 1.569 / 14.062 | 0.187 / 1.486 / 13.224 | 0.148 / 1.442 / 12.269 | 0.145 / 0.634 / 3.224 |
| 聚簇 | 2,473 | 11,798 | 0.261 / 0.140 / 0.780 | 0.137 / 0.140 / 0.767 | 0.187 / 0.142 / 0.765 | 0.153 / 0.311 / 1.254 | 0.140 / 0.110 / 0.341 |
| 薄片 | 829 | 3,400 | 0.279 / 0.120 / 0.478 | 0.127 / 0.074 / 0.285 | 0.183 / 0.128 / 0.515 | 0.156 / 0.258 / 0.723 | 0.149 / 0.066 / 0.175 |

**候选对输出。** 在密集场景中，Morton 串行遍历耗时 14.06 ms。原子批量输出的单线程版本耗时 32.15 ms，四线程版本耗时 13.37 ms。三者对应的峰值工作集为 13.58、8.86 和 9.67 MiB。两种批量输出都超过了初始的 256 对容量，均经过两遍收集。在稀疏场景中输出 348 对候选时，原生遍历耗时 0.066 ms，四线程批量收集耗时 0.834 ms。

**元数据过滤。** 下表统计生成全部自相交对的过程。密集场景中，两种实现均访问 1,060,976 个节点、剪除 32,346 个子树。缓存使查询源元数据读取次数从 402,840 降至 1,024。同场景整批盒查询的读取次数从 39,936 降至 128。

| 场景 | 保留对数 | 源元数据读取次数，无缓存 / 缓存 | 候选对耗时（ms），无缓存 / 缓存 |
| --- | ---: | ---: | ---: |
| 稀疏 | 41 | 1,709 / 1,024 | 0.154 / 0.147 |
| 密集 | 32,002 | 402,840 / 1,024 | 6.039 / 5.334 |
| 聚簇 | 1,274 | 23,514 / 1,024 | 0.592 / 0.562 |
| 薄片 | 608 | 7,671 / 1,024 | 0.378 / 0.365 |

**连续运动。** 八次更新中，SAP 调整了 4,096 个 X 轴端点，共交换相邻端点 74,034 次。BVH4 重新计算了 2,136 个分支的包围盒，拓扑重建次数为零。每个快照中，重建与增量更新版本返回的候选集完全一致。

| SAP 重建 | 0.158 | 1.237 | 2.701 | 10.569 | 5.64 |

| BVH4 重建 | 0.192 | 1.475 | 1.079 | 6.740 | 5.61 |
| BVH4 重拟合 | 0.228 | 0.536 | 1.096 | 6.828 | 5.65 |

**SDF 烘焙。** 在相同的 102 × 102 × 41 网格上，中位数树耗时 285.23 ms，Morton 耗时 232.70 ms，加速比为 1.23。两者的峰值工作集均为 8.22 MiB，十次烘焙的全网格指纹均为 `44b393a77a0a32d6`。

## 负载与测量方法

五种几何查询实现使用相同的包围盒。[中位数树](../geometry/spatial-index.zh-CN.md) · [Morton LBVH](morton-lbvh.zh-CN.md) · [四叉 BVH](four-way-bvh.zh-CN.md) · [扫描裁剪](sweep-and-prune.zh-CN.md) · [无栈遍历](stackless-lbvh.zh-CN.md)

候选对批量输出、元数据过滤和增量快照也沿用这些场景，分别按照各自的查询语义测量。[批量候选对输出](batched-overlap.zh-CN.md) · [元数据过滤](metadata-pruning.zh-CN.md) · [增量更新](incremental-updates.zh-CN.md)

每个静态场景包含 1,024 个包围盒和 128 次盒查询。稀疏场景的盒中心在各轴 81 个整数坐标中取样。密集场景将较大的盒压缩到各轴 13 个坐标内。聚簇场景有八个分离的簇。薄片场景在间距很小的 13 层 Z 坐标上放置薄盒，其中包含零厚度盒。每批查询选取 96 个条目盒、16 个角点和 16 个在场景外的盒。MT19937 以 20261121 为种子生成整数坐标，驱动程序按降序分配唯一 ID。[场景生成器](../../tests/fixtures/SpatialBenchmarkScenes.h)

运动场景沿用聚簇初始布局，每帧移动同一组 256 个物体，各轴位移为 +0.25 或 −0.125，连续八帧。实验分别计量初次构建和之后八次快照替换，查询耗时与候选数量覆盖全部九个快照。SAP 和 BVH4 都测量逐帧重建和增量更新。过滤场景在启动构建计时前为当帧条目标注元数据。

SDF 实验使用 40 × 40 × 10 mm 的板，中央有 10 × 10 mm 的通孔。两种实现均使用单线程、0.5 mm 网格间距和 5 mm 外围填充，X、Y 轴偏移半个网格。计时覆盖完整的 `BakeDenseSdf` 调用，包括对网格几何的查询和距离场数据分配。[带孔板测试模型](../../tests/fixtures/ThroughHolePlate.h)

在库版本 `3e385bf` 上，426,564 个节点中有 14 个节点的距离不同，最大差异为 7 ULP（8.67 × 10⁻¹⁹ m），所有节点的符号一致。在一个板角附近，两个三角形分别用自己的归一化尺度计算到同一顶点的距离，舍入误差改变了最近面遍历的剪枝结果。修复后，顶点命中使用网格中的原始坐标，快速估计值若低于三角形包围盒提供的保守距离下界，则重新精算。两棵树在该节点均选择面 2，得到与解析值相同的 0.00093541434669348292 m，整个网格逐位一致。回归用例还检查不同缩放尺度的三角形在共享顶点和共享边上等距时选择最小面 ID。[最近点回归测试](../../tests/install-consumer/TriangleMeshQueries.cpp)

盒查询耗时覆盖每个快照的一批查询。自相交对耗时覆盖全部相交的闭区间盒对，包含分配结果缓冲、算法内部排序和溢出重试。程序对每次计时调用实际返回的 ID 及有序 ID 对进行穷举校验，校验在读取时钟和内存计数器之后执行。过滤条件要求两个条目具有不同 owner 和相同 category，两种过滤实现接收相同的标签和谓词。[基准驱动程序](../../tests/install-consumer/SpatialBenchmark.cpp)

每个样本在独立进程中运行。各轮更换首个测量项，并交替反转执行顺序。Windows 记录进程峰值工作集，Unix 记录峰值常驻内存，采样时查询结果或烘焙网格仍然驻留。数据包含运行时、输入、索引、结果缓冲和先前帧造成的峰值，无法据此单独推算索引分配量。JSON 记录每次计时值（毫秒）、内存（字节）、逐帧候选数、算法工作量计数、编译器和可执行文件指纹。[机器可读测量结果](cpu-results.json)

## 复现

在已准备好的 Windows 检出目录中运行已安装软件包检查和基准程序。

```powershell
./scripts/environment/VerifyCpp.ps1 -Presets windows-release
python experiments/spatial/measure.py build/installed-tests-windows-release/hibiki_spatial_benchmark.exe --library-revision (git rev-parse HEAD) --output cpu-results.json
```

已安装软件包的 CTest 用例 `spatial.benchmark_smoke` 在小场景中运行全部算法，逐位核对两个烘焙网格。完整实验要求 Release 构建，并检查两种完整查询实现和各轮重复实验得到的网格尺寸和全网格指纹一致。
