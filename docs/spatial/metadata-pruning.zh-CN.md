# 带元数据的 LBVH 剪枝

[English](metadata-pruning.md) | **简体中文**

`FilteredMortonPlugin()` 注册带过滤能力的重叠查询提供者。每个叶子携带由调用方定义的归属与类别两个标签。仅当所有后代叶子的标签相同，节点才记录该统一摘要。查询谓词接收两组元数据，要求确定且无副作用。谓词排除统一摘要时可跳过整棵子树。混合节点继续下降，叶子执行精确过滤。

单盒查询使用指定源 ID 的元数据，包围盒与谓词允许时可命中自身。无序自配对只输出一次，较小 ID 的标签作为谓词第一参数。普通重叠查询覆盖原始候选。基线在每次谓词求值时读取查询侧元数据。每次查询独立记录访问节点数、查询元数据读取次数、叶测试和剪掉的内部子树。

## 缓存查询侧标签

`CachedFilteredMortonPlugin()` 在 `FilteredSpatialSlot()` 中注册 `hibiki.cached_filtered_morton`。若该槽位已有基线实现，可用 `config.Replace(CachedFilteredMortonPlugin())` 切换。独立调用方可包含 `<HibikiPhysics/FilteredSpatialIndex.h>`，通过 `MakeCachedFilteredMortonProvider()` 构造提供者。

缓存版本在检查根节点前，将源条目的两个标签复制到本次遍历的局部变量中。单盒查询复用源 ID 校验时找到的记录。全配对查询针对每个源叶子读取一次标签，并在该叶子的遍历中复用。`mQueryReads` 统计从索引读取源元数据记录的逻辑次数。缓存版单盒查询即使未命中根节点也计一次读取，N 个叶子的全配对查询计 N 次。两种实现共用相同的节点摘要和遍历逻辑，谓词与输出顺序一致。

### Release 实测

实验在 32 × 16 的网格上放置 512 个盒子，每个盒子在 X、Y 方向各覆盖两个网格间距。混合场景中，每个 4 × 4 区块内的归属与类别相同。谓词接受源归属编号较小或类别不同的组合。树外查询为每个源 ID 各执行一次与整棵树分离的盒查询。建树和完整有序候选集的比较在计时前完成，计时包含结果分配与排序。[实验源码](../../experiments/spatial/query-metadata/QueryMetadata.cpp)

| 负载 | 候选数 | 访问节点 | 叶测试 | 剪掉的子树 | 源记录读取次数，基线 / 缓存 | 耗时，基线 / 缓存（µs） |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 同标签全配对 | 0 | 512 | 0 | 512 | 512 / 512 | 3.22 / 3.45 |
| 混合标签全配对 | 1,806 | 23,552 | 3,948 | 1,472 | 10,892 / 512 | 95.84 / 92.60 |
| 树外盒查询 | 0 | 512 | 0 | 0 | 0 / 512 | 6.22 / 5.44 |

在 Windows x64、Ryzen 7 9700X、clang-cl 22.1.6 Release 下，缓存将混合标签全配对耗时降低了 3.4%。同标签场景在根节点剪枝，两种实现的读取次数相同，缓存版多用 0.23 µs。树外场景每次查询多读取一条源记录，这次实测中缓存版仍更快。表中的耗时取五个独立进程中位数的中位数。每个进程先预热两种实现，随后交替变换执行顺序，各测 21 组，每组重复十次完整负载。

```powershell
1..5 | ForEach-Object { & ./build/installed-tests-windows-release/hibiki_query_metadata.exe }
```
