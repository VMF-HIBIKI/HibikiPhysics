# CPU 扫描剪枝

[English](sweep-and-prune.md) | **简体中文**

包含 `<HibikiPhysics/SweepAndPrune.h>`，调用 `MakeSweepAndPruneProvider()` 即可构建 CPU 重叠索引。通过插件系统选择该实现时，将 `SweepAndPrunePlugin()` 添加到 `CapabilityConfig`。如果 `SpatialOverlapSlot()` 已注册其他提供者，则使用 `Replace`。实现 ID 为 `hibiki.sweep_and_prune`。[空间索引接口约定](../geometry/spatial-index.zh-CN.md)

每个条目拥有调用方提供的唯一 ID，包围盒各轴为有限闭区间。索引拥有自身数据，两类查询均可并发执行。共面、共棱或共顶点均计为重叠，任意轴的宽度可为零。条目或查询的端点非有限、条目 ID 重复时抛出 `std::invalid_argument`。

## 端点与查询

构建时按 ID 排列条目，存储各包围盒在 X 轴上的起点和终点。X 坐标相同时，起点排在终点之前，同类端点按 ID 排序。因此，一个点同时位于两个盒子的相接面上时，扫描能够找到两个盒子。

`OverlapPairs()` 从左到右扫描端点。遇到起点时，将新进入的盒子与活动集合中的每个盒子进行 Y、Z 两轴的区间相交测试。X 区间相交的两个盒子恰好在较晚的起点处检测一次。遇到终点时，以常数时间移除对应盒子。每对结果中较小 ID 在前，所有结果按字典序排列。

`Overlaps(bounds)` 通过两次二分查找缩小范围。查询区间右侧的起点可以直接排除。已遇到的起点所对应盒子的最大右端点构成前缀最大值，利用它可跳过一段全部在查询左侧结束的盒子。随后检查范围内的起点，并按 ID 升序返回结果。

构建 `n` 个盒子的索引耗时 O(n log n)，空间为 O(n)。若有 `c` 对盒子的 X 区间重叠，实际三维相交对数为 `k`，枚举耗时 O(n + c + k log(k + 1))，辅助空间与结果空间合计 O(n + k)。盒子在 X 轴上分离时，活动集合较小。若所有 X 区间重叠，即使盒子在 Y 或 Z 上分离，仍需检测二次量级的候选对。单盒查询访问 `v` 个端点并返回 `h` 个结果时，耗时 O(log(n + 1) + v + h log(h + 1))。
